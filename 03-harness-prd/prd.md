## 01 Context · Data Requirements

**Required sources, and exclusions**

Required Sources & Exact Systems
To generate high-confidence, traceable product insights, Juno's ingestion pipeline pulls directly from the following explicit systems and documents:

Productboard CSV Exports: Quarterly feature request dumps, user segment votes, and prioritization tags.

Customer Success & Support Systems: Zendesk/Intercom support ticket transcripts, error logs (e.g., Error 403 reports), and urgent account escalation threads.

Research & Discovery Repositories: User interview transcripts (e.g., User Sarah/Data Analyst session logs), Job-to-be-Done (JTBD) research notes, and qualitative survey free-text data.

Sales CRM Records: Enterprise prospect call notes from HubSpot/Salesforce (detailing major deal blockers like Okta SAML/SSO requirements).

Engineering Monitoring Channels: Internal technical telemetry and Slack alerting logs (e.g., #backend-monitoring API redlining and queue health metrics).

Deliberately Left Out
To prevent model hallucination, security breaches, and analytical noise, the following inputs are deliberately excluded from Juno's context window:

Live Production Database Credentials & Access: No direct SQL or live server access is permitted.

Raw Financial Ledgers & Revenue Models: Company-wide financial spreadsheets and ARR targets are omitted to prevent the model from generating hallucinated valuation or financial metrics.

Unverified External Web Scrapers: Third-party web data streams or unstructured public social media feeds outside of designated CRM and support channels.

**How fresh must it be**

Freshness SLA: Artifact inputs are refreshed synchronously upon ingestion per session, or via automated weekly CSV drops. Real-time engineering Slack logs and support tickets are pulled on-demand per execution run to ensure immediate reflection of system bottlenecks.

Handling Unreachable or Corrupted Sources: If a source file or CSV export is corrupted, missing required columns, or exceeds token safety limits, the harness triggers an automated truncation protocol, logs the warning, and explicitly flags the affected rows or missing files in the citation block rather than attempting to fabricate data.

## 02 Tools · System Capabilities

**The verb list**

The Verb List (Allowed Functions & Side-Effect Classes)
The model is granted execution access strictly through a bounded set of deterministic functions and reasoning verbs. Every action is categorized by its side-effect class to ensure complete governance:

parse_artifacts(stream) — [Class: Read]

Ingests, tokenizes, and clusters raw unstructured text from multi-source files (Productboard CSVs, customer interview transcripts, support tickets, executive emails, sales CRM call notes, and engineering Slack feeds).

score_matrix(dataset) — [Class: Read/Draft]

Executes deterministic scoring algorithms to map out Value vs. Impact matrices and RICE prioritization scores.

generate_spec(synthesis) — [Class: Draft]

Structures synthesized data into execution-ready PRD modules, MoSCoW scoping parameters, and Amazon-style PR/FAQ narratives.

render_wireframe(component_data) — [Class: Draft]

Generates low-fidelity structural blueprints, markdown tables, or component layout specs compatible with Wireframe.cc / Tailwind UI viewports.

flag_risks(spec_stream) — [Class: Read/Draft]

Scans inputs and outputs for technical debt, API redlining warnings, and enterprise deadline conflicts, organizing them by severity rankings.

**Deliberate omissions**

Deliberately Omitted Tool 1: Direct Production Database Write Access (SQL / Production DB Edit)

Why: Giving an AI agent direct write or migration access to live databases (like the legacy reporting database mentioned in the Slack logs) poses an existential risk of dropping tables, corrupting user data, or triggering production outages. Juno is strictly restricted to reading exported text streams.

Deliberately Omitted Tool 2: Automated Jira/Linear Board Mutation (API Task Creation)

Why: While Juno can draft MoSCoW scopes and actionable steps, it is intentionally blocked from automatically pushing tickets or changing statuses in external engineering trackers (Jira/Linear). This forces the human PM to review and sign off on all requirements, preventing automated noise from flooding developer backlogs.

Deliberately Omitted Tool 3: External Commercial Communication (Auto-Email / CRM Write)

Why: Juno cannot send automated emails or update live CRM records (e.g., promising enterprise prospects like Acme Corp delivery dates for Okta SSO). All external commitments require human validation to protect company liability and legal agreements.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

Turn Ceiling & Escalation Trigger: Single-pass chain-of-thought execution loop for synthesis. The loop halts immediately and hands back to a human PM if:

Direct contradictions arise between critical artifacts (e.g., executive mandate conflicts directly with technical safety limits).

Zero valid source citations can be mapped to a high-priority feature request.

Stop Condition: Stops automatically once all eight standard output sections (Executive Summary, Traceable Insights, Value vs. Impact Matrix, PR/FAQ, MoSCoW Scope, Wireframes, Risk Analysis, and Actionable Next Steps) are fully populated.

**Latency and cost target**

Latency and Cost Target: Answers back in under 8 seconds almost every time, and cost per task stays predictable. (Remember turns multiply, they do not add).

## 04 Memory · Data Requirements

**What persists, at what scope**

What Survives: The structured markdown report, updated skill parameters, and traceable citation logs persist within the session workspace and notebook context.

**Expiry and write rules**

What Expires: Transient raw prompt scaffolding and intermediate reasoning tokens are discarded. Only the human PM has write permissions to permanently update the system prompt or skill definition.

Audit Persistence: Each generated report must be timestamped and version-locked (e.g., v1-output-YYYY-MM-DD). Historical runs cannot be silently overwritten, ensuring the CPO can track how product recommendations evolve as raw signals shift.

## 05 Permissions · AI Risks & Mitigations

**The permission tier**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

**Justification**

Autonomy Tiers: Ingest raw text data, cross-reference sources, draft specifications, and structure ideas into standard templates without asking.

Tiered Safeguards: Because it cannot push code or modify live task trackers, its potential blast radius is low. However, high-impact decisions (such as pausing executive AI initiatives or committing to enterprise delivery dates like the Okta SSO deadline) require explicit human-in-the-loop sign-off.

Binding Commitment Restrictions: Juno is strictly forbidden from outputting definitive external delivery dates or financial commitments in the "Actionable Next Steps" or "PR/FAQ" sections; all timelines must be flagged as Proposed Estimates requiring Engineering sign-off.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

Citation Cross-Reference Rule: Every synthesized insight must contain an explicit bulleted citation pointing to the exact document and paragraph/row (e.g., Artifact 1 [Paragraph 1]). The verification check must validate that the cited row or paragraph index physically exists within the ingested source bounds. If an index is out of bounds or non-existent, the verification check fails and triggers an automated re-synthesis pass.

Wireframe Consistency Rule: Visual wireframe components generated via Wireframe.cc or layout mapping must strictly align with the MoSCoW "Must Have" feature scope; any unbacked UI elements trigger a re-synthesis pass.

**Failure behaviour**

Failure Handling: If an insight lacks a verifiable trace or relies on unbacked assumptions, the output is rejected or flagged for manual review before the CPO or engineering lead ever sees it.
